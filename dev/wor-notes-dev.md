# WoR Gear Builder — notes de dev (pour amorcer une nouvelle session / Claude Code)

**Livrable** : `wor-regles-tri.html` — SPA autonome, 1 seul fichier, vanilla JS/CSS, zéro dépendance, zéro réseau (exception opt-in : raccourcisseur da.gd au clic « Partager », repli lien long compact). Hébergée sur GitHub Pages.

## Architecture
- Tout dans un `<script>` : données → état → persistance → moteur → composants → vues → routeur → export/import/print → éditeur → handlers (délégation `document.addEventListener`) → drag&drop → boot.
- **i18n** : `const I18N = {fr:{…}, en:{…}}` + `t(clé, ...args)` (valeurs chaînes ou fonctions, fallback fr). Statiques HTML via `data-i18n` / `-ph` / `-title` / `-aria` + `applyLang()`. Défaut = langue navigateur, persisté (`lang`). Toggle = seg `[data-lang]` dans la sidebar. Référence = deux templates complets `refFR()` / `refEN()`.
- **Ne jamais traduire** : noms d'onglets, noms de règles, rôles créés par l'utilisateur. Rôle builtin `inspire` → « Inspiration » (fr) / « Inspire » (en), via `ARCH_LABELS[lang]`.

## Données
- 48 sets, clés canoniques **EN** (T∞ = noms wiki : Goldmane, Drakefire, Greyfang). Chaque entrée : `{n, t(0-4; 4=T∞), side, bFr, bEn, src|srcFr+srcEn, to?}` ; `to` = tableau de clés EN ou sentinel `"T23DPS"`.
- `SET_FR` (affichage fr), `FR_TO_EN` + `fixSet()` migrent les vieux noms FR à l'import/restauration. `SIDE_SETS`/`SETSIDE`/`SETTIER`/`SET_BY` dérivés de `SETS` — ne jamais dupliquer en dur (et déclarés **après** `SETS` : TDZ).
- 11 stats, ordre `ALLSTATS` : ATK, ATK%, CC, CD, HP, HP%, DEF, DEF%, RR, HE, AS.

## Moteur (sémantique in-game confirmée)
- Règle : sets · mains (**OU**) · pool de subs · ★ essentiels (⊆ pool) · requis 1-4.
- **Builder officiel** : le main effectif de la pièce est **neutralisé** des critères de subs (★ et comptage) → chevauchement mains/pool légal. `matchSubs(rule, subs, main)`.
- Chaque ★ restant = ET strict ; requis compté sur toute la liste, ★ incluses.
- Contraintes de mains par slot (éditables, Testeur) : arme=ATK, torse=HP ; bracelet sans AS/RR (CC exclusif) ; collier sans CC/RR (AS exclusif) ; bague sans CC/AS (RR exclusif).
- **Invariant de test : couverture exhaustive = 172 410 profils.**
- **Disponibilité des sets (générateur d'échantillon)** : `SET_AVAIL` dérivé des libellés `src` « GRn · a-b » (Raid équip. n, niveaux a-b) ; T∞ = Raid 1 (gauche) / Raid 3 (droite) niv. 19-24 ; Donjons d'équip. (niv. 1-13) : T1 dès le niv. 1, T2/T3/T∞ dès le niv. 3, jamais de T0 (`GD_MIN_BY_TIER`).
- **Taux de drop mesurés (niv. 21, appliqués à tous les niveaux)** : `RAID_TIER_RATES` — **GR1 ≠ GR3** (l'hypothèse « même table » est morte). GR1 : 183/1089 T∞ · 189/1089 T2 · 717/1089 T1 (710 runs GR1 21 cumulés : 340+370). GR3 : 40/418 T∞ · 76/418 T2 · 302/418 T1 (279 runs cumulés : 40+119+120). GR2 : 0,38 T2 · 0,62 T1 (pré-T∞, ~147k runs GR3 21) — aucune mesure post-T∞ pour GR2. Anciennes observées depuis : 8/2032 (~0,39 %) — le 0,87 % historique est conservé mais commence à sembler haut, à surveiller quand l'échantillon grossira. `ANCIENT_RATE` = 0,87 % : proba qu'une pièce arme/torse de raid soit « ancienne » (seules à pouvoir tirer la sub RR — sinon RR retiré du pool de subs). Pondération et anciennes : **mode « Raids & donjons » avec source raid uniquement**, et seulement si le scope ne contient pas de T0 (bas niveaux → uniforme) ; donjons et mode « Tiers & ensemble » : uniforme, RR libre (comportement historique). Le niveau 21 est marqué « 21 ★ » dans le sélecteur ; chiffres exposés dans `hint_scope` + encart « Taux de drop mesurés » de la Référence (FR/EN) — mettre à jour les 3 endroits ensemble quand les mesures s'affinent. Mode Couverture non affecté (toujours exhaustif).
- **Scope de l'échantillon = deux modes EXCLUSIFS** (`UI.test.scopeMode`, seg `data-tsscope`) : « Raids & donjons » (défaut, chips `data-tssrc` Raid 1/2/3/Donjon + select niveau `ts-lvl`, plafonné 13 en donjon) OU « Tiers & ensemble » (chips tiers + ensemble). Pièces + Générer dans le même bloc, en queue.
- **Couverture** : la colonne « gardées par elle seule » (`th_uniq`) a été SUPPRIMÉE (embrouillait) — `c.uniq` reste calculé car il alimente la lecture « doublon » (u===0). `computeCoverage` renvoie aussi `overlap[A][B]` = nb de profils gardés par A ET B, et `perSetMain[set][main]` = profils gardés par (set, main). La lecture « doublon » liste les règles recouvrantes en rulerefs cliquables. Deux accordéons : « Chevauchements entre règles » (paires triées par recouvrement décroissant, avec % de chaque règle — 100 % = doublon) après la table ; « Mains non couverts sur les sets ciblés » (par set gardé, les mains légaux du côté qu'aucune règle ne couvre) après « Sets non couverts ». Mobile : cartes en 3 lignes (nom `.td-name` en titre, chiffres `.td-mid` inline 33 %, lecture).
- **Pièce manuelle / explications** : `explainPiece` cumule TOUTES les raisons d'échec par règle et les renvoie en **tableau `reasons`** (rendu en sous-liste `.xr-line`, une raison par ligne) ; l'affichage des règles proches et des verdicts porte **id · nom** partout (`matchedNames` renvoie « G1 · Nom »). Dès **2 subs saisies**, un panneau « Règles encore compatibles / qui couvrent ces subs » liste les RÈGLES encore satisfiables (main ok + ★ manquantes ≤ positions libres + requis encore atteignable) — ruleref cliquable + nom + sets en discret (l'ancienne version listait les SETS : rejetée, « on s'en fout des sets, on veut les règles »). Panneau NEUTRE (pas de liseré : informatif — le liseré vert contredisait un verdict rouge quand les règles couvrantes ciblent d'autres sets), hint `m_rulescov_hint` expliquant la condition de set, et par règle la ligne des manques : `manque : ★ X · n subs parmi …` (`rc_miss_pre`/`rc_miss_more`) ou `subs au complet` (`rc_ok`). Ordre des encarts de résultat : verdict → règles couvrantes → règles proches. Le verdict est un panneau seul (✓/✗) ; les règles proches vivent dans un panneau SÉPARÉ sous-titré `m_near_sub` (« Règles proches — ce qui leur manque… »), raisons en sous-lignes espacées. **Flux inversé + sélecteurs façon éditeur (plus AUCUN `<select>`)** : slot = segmenté (`data-tmslot`), main = chips single-select (`data-tmmain`, vide les subs en conflit), set = grille ordre in-game (`data-tmset`) avec quick-filtres de tier en filtre d'AFFICHAGE (`data-tmtier`, `m.tierFilter`), bouton « vider » (`#tm-clear`). Les handlers `change` tm-slot/tm-set/tm-main ont été supprimés. **Layout = stepper `.tm-step`** (variante C validée sur maquettes) : 4 étapes Slot/Main/Subs/Set, en-tête cliquable `data-tmstep` = label + valeur courante + chevron, TOUTES PRÉ-OUVERTES (`m.steps`, runtime), repli manuel. L'en-tête est un `<div role=button>` (pas un `<button>`) pour héberger « vider » (`#tm-clear`) dans l'en-tête Subs — l'ORDRE des handlers compte : `#tm-clear` est testé AVANT `data-tmstep` dans le listener click, sinon vider replierait l'étape. Conteneurs `.tm-stats`/`.tm-sets` : flex-wrap en desktop, **grilles uniformes en mobile ≤680px** (stats 6 colonnes, sets 2 colonnes, seg 5 colonnes) → plus de chips orphelines en fin de ligne. Le résumé d'en-tête reste vrai même si le filtre de tier masque le set sélectionné dans la grille. L'encart « Mains non couverts par set » de la Couverture a été SUPPRIMÉ (jugé inutile — `perSetMain` retiré de `computeCoverage`). Libellé chevauchements clarifié : « N pièces gardées par les deux règles à la fois — soit X % de tout ce que garde A, et Y % de ce que garde B » (`ov_row`). Jeu de test réel : `wor-regles-end-game-strict-import.json` (18 règles, clé ODM1OTE=).
- **Mobile** : `.app{grid-template-columns:minmax(0,1fr)}` (sans le 0 → min-width:auto → la rangée d'onglets gonfle la page = scroll latéral) ; `.strip` en 2 colonnes ; noms de sets/règles = titres de carte dans les tables empilées (`.td-name`).
- **Style des textes explicatifs** : les petits laïus multi-idées se rédigent en `<ul><li>` (styles `.hint li`), pas en phrases enchaînées par des tirets (cf. `hint_rules`, `hint_scope`). **Piège** : le conteneur doit être un `<div class="hint">`, jamais un `<p>` — un `<ul>` est interdit dans un `<p>`, le parseur ferme le `<p>` avant la liste qui perd alors tous les styles hint (texte « énorme »).

## IDs & persistance
- IDs de règles : `G{n}` (2 pièces) / `D{n}` (3 pièces), **numérotés PAR ONGLET** (chaque onglet repart à G1/D1 ; deux onglets peuvent porter le même id). Plus de compteur global `seq` : `nextRuleId(tab, section)` = max+1 dans l'onglet. `getRule`/`tabOfRule` résolvent d'abord dans l'onglet actif. `migrateRuleIds()` renumérote chaque onglet à CHAQUE chargement (positionnel, dans l'ordre des règles — un drag & drop se reflète dans les ids au reload) ; couvre les vieux R/P et les compteurs dérivés. À l'édition, changer d'ensemble migre le préfixe (numéro conservé si libre, sinon max+1).
- **ENTERED scopé par onglet** : clés `tabId:ruleId` (`entKey`), lecture via `isEntered(rid)` (onglet actif). Vieux format non scopé migré au restore (avant `migrateRuleIds`). Dupliquer un onglet conserve les ids mais repart avec « saisie » décochée.
- Payload v4 : `{v, consV, tabs, active, entered, constraints, theme, acc, dens, lang, xarch, tabSeq}` — storage Claude sinon localStorage. `sanitizeRule` filtre/migre tout import.
- Export JSON par onglet `{format:"wor-tri-rules", version:1, tab:{name, key?, rules[] sans id}}`.
- **Clé in-game par onglet** (`tab.key`, ≤60 car. ; le code du jeu fait 8 caractères) : rangée `#tab-key` dans la barre d'onglets (sous les boutons, au-dessus des filtres) — panneau mis en avant (liseré accent), champ compact 13ch + bouton copier (`#tab-key-copy`, focus le champ si vide). Persistée (payload tabs), restaurée, copiée à la duplication d'onglet, transportée par l'export JSON (`tab.key`) et le lien de partage v2 (champ `k`) — celui qui importe l'ensemble récupère la clé à taper en jeu.
- **Lien de partage** `#/import=` : format v2 compact préfixé `2.` = `{v:2,n,r:[[name,sets,mainsMask,poolMask,essMask,req,archs|0]…]}` → JSON → `CompressionStream("deflate-raw")` → base64url (`encodeShare`/`decodeShare`, ~6× plus court que le v1). Masques de stats sur **STAT_CODE, ordre FIGÉ à jamais** (indépendant de ALLSTATS qui n'est que l'ordre d'affichage — le réordonner ne doit pas casser les liens émis). Fallback sans CompressionStream : lien long v1 (b64 du JSON d'export) ; les liens v1 restent importables.
- **Raccourcisseur = TinyURL, secours da.gd** (1pt.co est MORT — DNS ne résout plus). `shortenShare` : 1) TinyURL `api-create.php?url=…&alias=WoR-{6 base36}` → `https://tinyurl.com/WoR-xxxxxx`, **301 direct sans interstitiel**, fragment conservé, collision alias = 422 → 3 essais, timeout 8 s (le 1er hit à froid dépasse 5 s — c'est ce qui faisait tomber sur le secours) ; CORS : l'ACAO TinyURL n'est renvoyé QUE si la requête porte `Origin` (fetch le met ; un curl nu ne le voit pas). 2) Secours da.gd `shorten?url=…` (CORS `*`, couvre file://) — **da.gd affiche une page interstitielle anti-phishing sur tout lien plus jeune que `shorturl_interstitial_cooldown` (source dagd, défaut 3600 s)**, d'où son éviction comme primaire. 3) Repli lien long (toast `t_share_fallback`). Seule exception réseau de l'app.
- **Langue** : défaut = `navigator.language`, persistée UNIQUEMENT après clic sur le toggle (`LANG_CHOSEN`, `payload.lang=null` sinon) — un visiteur sans choix explicite suit toujours son navigateur.
- **Boot** : `restoreState().then(route)` — router AVANT la restauration faisait écraser un import `#/import=…` par les onglets sauvegardés (perdu sans erreur dès que le storage n'était pas vide).
