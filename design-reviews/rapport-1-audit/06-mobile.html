Mobile — le téléphone est le terrain de jeu

Contexte assumé partout : le joueur tient son téléphone en portrait, une main, pouce droit, et alterne jeu ↔ app toutes les 20-60 secondes pendant le farm. Tout ce qui coûte un scroll, un tap en haut d'écran ou une re-saisie est facturé à ce tarif-là.

Ce qui marche — à conserver tel quel

  • Le fix anti-scroll-latéral (minmax(0,1fr)), documenté dans le CSS ;
  • Les inputs 16 px anti-zoom iOS ; le tiroir en 100dvh + transform (60 fps) ;
  • Les tables empilées en cartes (.rtable) — pattern solide, avec le raffinement des 3 chiffres en ligne ;
  • Les grilles uniformes de chips (6 col stats / 2 col sets) — mémoire musculaire : ATK% est toujours au même endroit ;
  • Boutons 40 px, primaire pleine largeur, zones de tap du « ? » étendues, fondu de débord des filtres.

P0 Les fragilités de l'existant

  • La rangée d'onglets scrolle sans indice de débord — le fondu n'est posé que sur les filtres, pas sur la rangée la plus importante de la vue ; et le « + » (créer un onglet) vit dans la zone scrollable : avec 4+ onglets il devient inatteignable sans savoir qu'il faut scroller. → masque étendu, « + » sorti du flux, fondu gauche conditionnel ;
  • Le contenu utile démarre sous la ligne de flottaison : burger + titre + lede + onglets + 5 outils en wrap + clé in-game + filtres + CTA = la première règle apparaît à ~460 px sur 812. Or Renommer/Dupliquer/Supprimer/Exporter sont des actions rares qui paient un loyer permanent. → replier les 5 outils derrière « ⋯ » sur l'onglet actif, clé in-game repliée. Gain ~120 px ;
  • Le « vider » manuel entre chaque drop de la pièce manuelle : friction n°1 du flux réel → auto-reset après verdict.

P0 Le parcours farm, chronométré

Vérifier UN drop aujourd'hui : alt-tab → (burger haut-gauche, la zone la plus hostile au pouce droit + Testeur) → mode Pièce manuelle → slot → main → « vider » → 4 subs → set (grille de ~25 + scroll) → scroll vers le verdict, qui est sous les 4 étapes — avec un layout shift à 2 subs quand le panneau des règles couvrantes s'insère. Total : 9-11 taps + 2 scrolls par drop, verdict hors écran au moment où il tombe.

Le vrai levier : le verdict n'a pas besoin de la saisie complète

Le moteur sait déjà raisonner sur une pièce partielle (« règles encore possibles »). Il suffit d'inverser la charge : tap 1 — Set : si le set n'est dans aucune règle → RECYCLE, verdict en 1 tap (statistiquement le cas le plus fréquent : 1-2 % de gardées) ; tap 2 — Slot·Main fusionnés (mains légales dépendent du slot ; slot mémorisé du drop précédent) ; taps 3+ — subs, verdict au fil de l'eau : la saisie s'arrête au verdict, pas à la complétude. Médiane réaliste : 2-4 taps par drop.

Auto-reset au verdict (timer 1,5 s annulable : subs vidées, set/slot conservés), zéro scroll, état persistant au retour d'alt-tab, wake lock pendant le mode.

P1 La recopie guidée — une règle par écran

Ressaisir 18 règles en alternant les deux apps : aujourd'hui il faut retrouver sa règle après chaque alt-tab et cocher une case de 17 px. Le mode plein écran : id + nom en 24 px, paires clé/valeur en 18-20 px sans abréviation ni chip — un écran à LIRE en coup d'œil depuis le jeu, pas une UI à manipuler. « Saisie ✓ Suivant » (56 px, bas d'écran) coche et avance ; reprise automatique à la première non-cochée ; swipe horizontal en plus des boutons ; wake lock.

P1 Navigation : tab bar basse plutôt que tiroir

Verdict tranché : le tiroir est le mauvais pattern pour cette app sur ce contexte.

  • 4 vues = le sweet spot d'une tab bar (un tiroir se justifie à 7+) ;
  • l'alternance Règles ↔ Testeur est un geste cœur : 2 taps dont un burger haut-gauche aujourd'hui, 1 tap en zone de pouce demain ;
  • la navigation devient visible (le tiroir cache l'existence même du Testeur à un nouvel utilisateur) ;
  • coût ~56 px + safe-area, remboursé par les 64 px du burger et les ~120 px d'outils repliés ;
  • ce qui reste dans le tiroir (import, thème, langue, accents) est du réglage, pas de la navigation → sheet « ⋯ » ; les modes plein écran masquent la tab bar (cohérent : ce sont des modes, pas des vues) ; desktop inchangé.
