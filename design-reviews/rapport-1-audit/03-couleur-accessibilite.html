Audit spécialiste · colorimétrie & accessibilité — ratios WCAG calculés

Couleur — la hiérarchie inversée, chiffrée

Tous les ratios ci-dessous sont calculés (luminance relative WCAG 2.x) sur les hex réels du CSS. Seuils : AA texte 4,5:1 · AA texte large 3:1 · AAA 7:1. Le petit mono 11-12 px omniprésent est jugé sur cible AAA recommandée / AA impérative. Verdict d'ensemble : le « confort nocturne » est bien calibré en haut de la gamme — c'est le plancher qui a traversé le seuil.

Sur une carte de règle ouverte : les chips de contenu mesurent 6,8 à 11,4:1, leurs labels « Rôles / Sets / Subs » mesurent 3,2:1 — les jalons structurels sont 2 à 3,5× moins contrastés que ce qu'ils étiquettent. Le balayage en F ne fonctionne plus : on lit le contenu avant sa structure. C'est exactement la plainte « les noms de sections sont moins visibles que les éléments qui les composent ».

L'échelle de luminance corrigée — 5 niveaux, plancher AA garanti

Principe : le contenu reste le texte le plus contrasté (c'est lui qu'on lit) ; ce qui doit être monotone, c'est la chaîne des jalons structurels, et aucun jalon textuel ne descend sous 4,5:1. Deux tokens naissent, --faint est requalifié en décor.

P1 L'or porte cinq sémantiques

① état sélectionné (onglets, nav, filtres) · ② marque/décor · ③ tier T2 · ④ ids de règles · ⑤ primaire + focus + progression. Un badge « T2 » doré côtoie un filtre doré actif : même couleur, deux sens sans rapport. Et aucun accent n'est neutre vis-à-vis des familles sémantiques :

Accent choisiCollision avecÉcart de contraste mutuel
ortier T21,00 — identique
vert« gardée », T∞1,03 / 1,45
bleuT01,25
violetT11,28
rouge« recyclée », T31,01-1,13 — le pire : sélection ≈ danger

Reco : réserver l'accent aux états d'interaction ; verrouiller « jamais un tier signifié par la couleur seule » (le texte T0…T∞ est déjà là — la collision or/T2 devient tolérable) ; retirer ou décaler l'accent rouge (#dd7f8f), a minima interdire l'accent sur tout contrôle destructif.

P1 Daltonisme : les verdicts reposent sur vert/rouge + un point de 8 px

#6fbf8f / #cf6054 convergent vers des bruns olive en deutéranopie et protanopie, et 8 px de teinte pure est invisible pour ~8 % des hommes. Redondances à ajouter : glyphe systématique ✓/✗ ; forme — point plein = gardée, anneau creux = recyclée ; bordure de carte continue vs dashed (dashed est déjà le langage « inactif » des chips — cohérent). Les familles de stats sont OK : toujours accompagnées du texte.

Autres constats

  • P1 Options cliquables à opacité .28/.32 (subs à cocher, sets du dialogue) : contraste effectif 2,3:1 — ce ne sont pas des éléments désactivés (exemption WCAG) mais des options. → opacité .5 minimum, le pointillé porte le signal ;
  • P2 Focus = couleur de l'état sélectionné : au clavier on ne distingue plus « focalisé » d'« actif » → anneau bicolore 0 0 0 2px var(--bg), 0 0 0 4px var(--acc) ;
  • P2 ::selection à 1,3:1 (or à 14 %) : la sélection de texte est quasi invisible → 35 % ;
  • P2 T1/T3 « bases » à 4,5-4,8:1 sur panel2 → #b58cee / #e87e75 ; T∞ #4ef08a quasi fluo → #3fd97a.

Ce qui est bien calibré — à conserver

Le « confort nocturne » (--ink #d9d2c4, 12,4:1) : au-dessus d'AAA, sous la zone de halation, teinte chaude qui réduit la dominante bleue. --ink-hi à 15,1 pour les titres : bon plafond. Le problème n'était pas le plafond — c'était le plancher.
